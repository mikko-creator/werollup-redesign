## 1. How the theme uses the plan

- `src/content/image-plan.json` is `{ slots: { <id>: { file, alt, role, kind, pages, phone?, video?, still?, sameAs?, twin?, aiLabel, uses } } }`.
  The pipeline reads `file`, `alt`, `role`, `pages`, `kind` and `video`. Every other field is for the theme lanes.
- **role** `hero`: the page-header art of the listed pages, a banner or the store hero. The build puts it in
  `page.generated.hero`. Each page has at most one. `art`: an atmosphere plate inside a band. `card`: a mega/sheet menu card,
  drawn by the chrome on every page, so `pages` is empty. Call `ctx.img(id)` directly. `cutout`: a protrusion (5.4).
- **alt** is `""` everywhere (DESIGN-SPEC 11: decorative). Pass `attrs: { "data-decorative": "" }`, otherwise build-check fails.
- **phone**: a 1170x960 crop of the same master for 390x320 banners at DPR 3 (R-2). It is a file ref: `ctx.img(slot.phone, …)`.
  The theme reads it from the JSON, because `ctx` does not expose the plan.
- **Two ids, one file** (`sameAs`): S-MIST is the banner of 9 pages and the 404, and S-MIST-BAND is the atmosphere plate on
  `/` and `/products/flower/`. S-DUSK-PALMS is a banner on 4 pages, and S-DUSK-PALMS-BAND is the home Community band.
  S-EDIBLES-BANNER is the 21:9 crop of the S-CARD-EDIBLES master that 10.4 names. The split keeps `page.generated.hero`
  unambiguous on every page. Variants are content-hashed, so a shared file ships once.
- **404**: `render404` has no page, so its banner is `ctx.img("S-MIST")`.
- **Video** (`kind: "video"`): `ctx.video(id)` returns null while the loop files do not exist (PIPELINE state `absent`).
  The theme then renders the still named in `still`. All three loops are declared with their final file names, so they
  appear without a theme change once they are generated.
- **CUT-LIGHTER `twin`**: the cut-out's box inside its photo (`x 207, y 310, w 523, h 686` of 1200x1600). H4 aligns the
  cut-out over `red-lighter-cards` in the Community light box with it.
