# COMMERCE: how shopping works on werollup.com

UNDERSTAND phase, COMMERCE lane, 2026-10-13. Written from files on disk only. No request went to werollup.com, iheartjane.com,
weedmaps.com or wm.store. The data version is `docs/data/commerce.json`, generated by
`tmp/understand/commerce/build-commerce.mjs`. It holds the full CTA map (87 groups), every crawled shop route and the
verbatim embed snippets.

## 0. The short version for build lanes

| | LAX - Culver City | San Pedro - Palos Verdes |
|---|---|---|

## 2. Shop routes and what the static rebuild must serve

All 47 shop records returned 200 from WordPress. The embed markup is the same on every record:

- The Jane blocks are byte-identical on all 28 San Pedro records (sha256).
- The Weedmaps tag is identical on all 19 Culver City records (grep).

Three pairs were diffed in full: the base page against `/shop/menu/flower`, against `?filters[root_types][]=flower`, and
against a `store_query` variant. Those differed only in the canonical link, the `overrides.css?v=` cache-buster, the
order of the randomised reviews, the hero image (it rotates on Culver City) and the nav current-item marking.

### 2a. Culver City (Weedmaps): query string only

The scheme is `/location/culver-city/shop/?store_path=<path>&store_query=<query>&locationId=10599`:

- `store_path` is `/` in every crawled link.
- `store_query` is the store's own URL query. Its brackets stay percent-encoded inside the value, so in the link they are
  double-encoded. Example: the link
  `store_query=filter%255BanyClientCategories%255D%255B%255D%3Dflower-category-pages%26sortBy%3Dmost_popular%26page%3D1`
  decodes once to `filter%5BanyClientCategories%5D%5B%5D=flower-category-pages&sortBy=most_popular&page=1`.
- `locationId=10599` and `sortBy=most_popular` appear on some links and not others (the pre-rolls, edibles, vape and
  concentrates cards on `/location/culver-city` omit both).
- Values seen:
  - Categories: `flower-category-pages`, `pre-rolls-category-pages`, `vape-pens-category-pages`, `edibles-category-pages`,
    `concentrates-category-pages`, `topicals-category-pages`, `accessories-category-pages`.
  - Brands (`filter[brandSlugs][]`): `wizard-trees`, `traditional`, `teds-budz`, `elusive`, `dime`, `710-labs`.
  - Best Selling: `store_query=page=1&sortBy=most_popular`.
- Owner: the WM Store script reads the host page's query. This is inferred from the parameter names and from the server
  returning the same page for every variant. The script's code is **UNVERIFIED**.
- Canonical: every variant points to `https://werollup.com/location/culver-city/shop/`.
- **Rebuild:** `/location/culver-city/shop/index.html` is enough. A static host ignores the query, and the script sees it
  in `location.search`. Also serve `/lax-menu/index.html`.

### 2b. San Pedro (Jane): two schemes

1. **Path routes** `/location/san-pedro/shop/menu/<category>`, crawled for `edible`, `extract`, `flower`, `gear`,
   `jane-gold`, `pre-roll`, `topical` and `vape`. Live, each 301s to the trailing-slash form and returns 200 with its
   own canonical, e.g. `https://werollup.com/location/san-pedro/shop/menu/jane-gold/`. The Jane app routes on the path
   after `partnerHostedPath`.
2. **Query filters** on the base page:
   - `?filters[root_types][]=`: `best_selling`, `flower`, `pre-roll`, `vape`, `edible`, `extract`, `topical`
   - `?filters[feelings][]=`: `Blissful`, `Creative`, `Energetic`, `Hungry`, `Pain+Free`, `Relaxed`, `Sleepy`
   - `?filters[brand][]=`: `710 Labs`, `Alien Labs`, `PlugPlay`, `ST IDES`, `WYLD`

   Live canonicals keep the query, e.g. `https://werollup.com/location/san-pedro/shop/?filters%5Bfeelings%5D%5B%5D=Pain+Free`.

**Rebuild.** Query variants work automatically on `/location/san-pedro/shop/index.html`. Each menu path needs a served
page. Compare the two ways to provide it:

| Option | How | Pros | Cons |
|---|---|---|---|
| A. One generated copy per known category | write `/location/san-pedro/shop/menu/<cat>/index.html` (8 files), each the San Pedro shop page with its own canonical | works on any static host with no config; real 200; keeps the per-path canonical | covers only the 8 crawled categories. Any other sub-path the Jane app creates while a visitor browses (product pages, other categories) 404s on reload or when shared. Those sub-paths are **UNVERIFIED**: none were crawled, and the Jane sitemap that would list them was not saved. |
| B. Fallback that boots the embed | a host rewrite `/location/san-pedro/shop/*` to the shop page with status 200 (Netlify, Cloudflare Pages, Vercel, nginx), or, on hosts without rewrites, a `404.html` that recognises the prefix and renders the shop page | any sub-path works, including routes nobody has seen yet | the rewrite depends on the host; the `404.html` variant answers with HTTP 404, so search engines drop those URLs and some link checkers flag them; and every unknown URL under the prefix shows a menu |

**Recommendation: A plus B.** Generate the 8 known category pages so they return a real 200 with the right canonical.
Add the rewrite (or, failing that, the 404 boot) for everything else under `/location/san-pedro/shop/`. Culver City
needs neither, because it routes on the query string.

### 3c. Does choosing a store change these targets? Yes, for three classes of link

Source: `assets/js/4c0935fa-main.js`, module 343 (offset 13726-15772, copy `tmp/understand/commerce/main-343.js`), and

## 5. Risks

Full text, status and how to test each one: `risks` in `docs/data/commerce.json`.

- **R1 (high, UNVERIFIED) Origin and path binding.** Jane's config carries `partnerHostedPath: "/location/san-pedro/shop"`.
  Embed config 989 is a partner-hosted config, presumably registered for werollup.com; nothing on disk shows Jane's
  origin settings. A preview on another host or under a sub-path (for example a GitHub Pages `/<repo>/...` URL) may show
